## 1. 技术选型

### 1.1 推荐方案

| 部分 | 选择 | 作用 |
|---|---|---|
| 语言 | TypeScript | 全部游戏代码 |
| 渲染 | PixiJS v8 | 2D 画面：水面、鱼、粒子、着色器 |
| 界面 | React + CSS | 背包、商店、笔记、鱼卡片等所有面板 |
| 桌面外壳 | Electron | 打包成 Windows / macOS 程序，读写存档 |
| Steam 接入 | steamworks.js | 成就、云存档、Steam 界面 |
| 音频 | Howler.js | 背景音乐循环、音效 |
| 构建 | Vite | 开发时热更新，秒级看到改动 |
| 测试 | Vitest（逻辑）+ Playwright（画面截图） | 自动化验证 |
| 数据校验 | zod | 检查配置表有没有写错 |

### 1.2 为什么不用之前建议的 Godot

之前按"PC 游戏"的常规思路推荐了 Godot 4。但这个项目的实际情况是**代码主要由 AI 来写**，这一点改变了结论：

1. **AI 最擅长 TypeScript**。Godot 4 的 GDScript 资料少得多，AI 还经常把 Godot 3 和 4 的写法搞混，出错率明显更高。
2. **全部是纯文本代码**。Godot 的很多工作要在编辑器里拖拽完成；这套方案没有这一步，任何 AI 都能改，改了什么在 git 里一目了然。
3. **我能自己验收画面**。我在云端环境里能直接运行游戏、截图、跑自动测试，自己检查"鱼好不好看、帧率够不够"，不用每次都等你手动看。Godot 在这种环境里很难做到。
4. **界面更容易做漂亮**。参考图里那种纸质卡片、宋体排版的界面，用网页技术（HTML/CSS）做最自然。
5. **路线成熟**。用网页技术做 2D 游戏上 Steam 已经有很多先例，比如《吸血鬼幸存者》最初就是用 Phaser + Electron 做的。

**代价**：安装包大一些（约 150MB，对 Steam 游戏无所谓）；性能不如原生引擎，但对这种规模的 2D 游戏完全够用；以后想上主机平台会比较麻烦（我们只做 PC，没影响）。

## 2. 架构

```mermaid
flowchart TB
    subgraph Electron[Electron 桌面外壳]
        Main[主进程：窗口 / 存档文件 / Steam]
    end
    subgraph Game[游戏]
        App[app 调度层：场景切换 / 输入 / 游戏循环]
        Sim[sim 逻辑层：纯计算，不碰画面]
        Render[render 渲染层：PixiJS]
        UI[ui 界面层：React]
        Data[(data 配置表 JSON)]
    end
    App --> Sim
    App --> Render
    App --> UI
    Data --> Sim
    Sim -- 状态 --> Render
    Sim -- 状态 --> UI
    UI -- 操作指令 --> App
    App <--> Main
```

### 2.1 四条硬规则

1. **逻辑层（sim）不能引用任何画面代码**。时间、天气、鱼的生长、遗传、经济、钓鱼判定全部是纯计算，所有随机数用可设种子的随机数生成器。这样逻辑可以脱离画面单独测试，也能跑几百天的数值模拟来调平衡。
2. **所有内容写在配置表里**。鱼、渔具、钓点、订单、NPC 对话都在 `data/` 目录的 JSON 文件里，用 zod 校验，加新鱼不改代码。
3. **界面只读状态、只发指令**。界面不直接修改游戏数据，所有改动通过指令交给逻辑层，避免状态混乱。
4. **存档带版本号**。每次存档结构变化都要写迁移函数，保证老存档永远能打开（加种田时尤其重要）。

### 2.2 目录结构

```
electron/            # 桌面外壳：窗口、存档读写、Steam 接入
src/
  sim/               # 逻辑层（纯 TypeScript，可单独测试）
    time/            #   游戏时钟、季节、天气
    rng/             #   可设种子的随机数
    items/           #   物品与背包
    fishing/         #   鱼的出现、咬钩、遛鱼判定
    pond/            #   鱼塘、个体生长、水质
    genetics/        #   锦鲤基因、遗传、品种判定、品相评分
    economy/         #   价格、市场波动、订单
    save/            #   存档结构与版本迁移
  render/            # 渲染层（PixiJS）
    water/           #   水面着色器：焦散光斑、波纹、折射
    fish/            #   程序化鱼：身体网格、摆尾、花纹贴图、投影
    flock/           #   群游算法
    fx/              #   雨、雪、落叶、萤火虫
    scenes/          #   鱼塘、钓点、家园图、地图
  ui/                # 界面层（React）：HUD、面板、对话
  app/               # 调度层：场景管理、输入、游戏循环
  audio/             # 音乐、音效
data/                # 配置表：fish.json、spots.json、items.json……
assets/
  raw/               # 其他 AI 生成的原始素材（你放这里）
  ...                # 处理后、游戏实际使用的素材（我放这里）
tools/               # 数值模拟脚本、素材批处理脚本
tests/
docs/
```

### 2.3 关键技术点

| 技术点 | 做法 | 风险 |
|---|---|---|
| 水面 | AI 画的池底图 + 焦散光斑着色器 + 点击 / 雨滴波纹 + 轻微折射 | 中，M0 验证 |
| 鱼 | 沿脊柱变形的网格实现摆尾，程序生成的花纹贴图，偏移的柔和投影（参考图里能看到） | **高，M0 重点验证** |
| 群游 | 群体算法（分离 / 对齐 / 聚合）+ 空间网格加速，目标 200 条鱼稳定 60 帧 | 低 |
| 锦鲤花纹 | 基因参数 → 多层噪声斑块 → 画到鱼身贴图上并缓存 | 中，M3 |
| 其他鱼种 | 每种鱼一套体型参数（长宽比、鳍的位置）和花纹规则（鲫鱼银灰、鳜鱼斑点……） | 低 |
| 钓鱼手感 | 张力、体力、挣扎模式全部参数化，内置调参面板，边玩边调 | 中，需要人试玩 |
| 调试工具 | 内置作弊面板：跳时间、改天气、刷鱼、加钱 | 开发和试玩必备 |
| Steam | steamworks.js 接成就和云存档；Electron 下的 Steam 界面需要特殊处理 | 低，M5 |

## 3. 分工：谁来做什么

### 3.1 先说清楚我做不了的

- ❌ **生成图片、音乐、音效、视频**：需要图像 / 音乐 / 音效 AI。
- ❌ **亲手玩游戏、判断好不好玩**：我能跑自动测试、截图检查画面，但"手感爽不爽""节奏拖不拖"必须由人来玩。
- ❌ **最终审美拍板**：AI 出图风格会有偏差，需要你来挑选和把关。
- ❌ **操作 Steam 后台、付款、报税**：只能你本人来。

除此之外，**代码、策划、数值、文案、程序化美术、素材后期处理**都可以由我来做。

### 3.2 分工总表

| # | 工作 | 谁来做 | 我给对方的输入 | 备注 |
|---|---|---|---|---|
| 1 | 策划、系统设计、数值平衡 | **Claude** | —— | 你审核拍板 |

### 3.3 要不要让其他编程 AI 一起写代码？

**建议不要混用不同家的编程 AI 写同一个代码库**。不同 AI 的写法、架构习惯差别很大，混在一起集成成本很高，容易越改越乱。

如果想加快速度，更好的做法是**同时开多个 Claude Code 会话**，按模块边界分工，比如：

| 并行任务 | 依赖 | 可以何时开始 |
|---|---|---|
| A. 项目骨架 + 逻辑层基础（时间、随机数、存档、配置加载） | 无 | 立刻（最先做） |
| B. 水面与程序化鱼（M0 技术验证） | 无 | 立刻 |
| C. 钓鱼玩法 | A | A 完成后 |
| D. 界面面板 | A | A 完成后 |
| E. 锦鲤遗传与花纹生成 | A、B | M2 之后 |
| F. Steam 接入与打包 | A | M4 之后 |

每个任务只改自己的目录，通过逻辑层接口互相配合。我负责定义接口、做集成审查。

如果你确实想用其他编程 AI（比如 Cursor、Codex），最适合交给它们的是**边界清晰的独立模块**（比如 F），并且要求它们遵守仓库里的规范文档（开工时我会写一份 `AGENTS.md`）。

## 4. 协作流程

1. **仓库是唯一的"真相源"**：文档、代码、素材全部进 git，任何 AI 都从这里读取最新情况。
2. **素材流程**：
   1. 你把[美术指南](art-audio-guide.md)里对应的小节复制给图像 / 音乐 AI 生成。
   2. 挑选满意的，按清单编号命名（如 `BG-001_a.png`），放进 `assets/raw/` 对应的文件夹。
   3. 在同名 `.txt` 里记下用了哪个工具、哪条提示词（将来 Steam 的 AI 内容声明要用）。
   4. 告诉我，我来处理、接入游戏，截图给你看效果。
3. **每个里程碑结束**：我出一个可运行的版本 + 截图或录屏 + 试玩清单；你玩完反馈，我们再定下一步。

## 5. 里程碑

| 里程碑 | 内容 | 验收标准 | 需要的素材 |
|---|---|---|---|
| **M0 技术验证** | 一个鱼塘画面：水面焦散、50~100 条程序化锦鲤群游、点击撒饲料抢食 | 截图接近参考图的质感；60 帧 | P0：池底图 1~3 张（没到位就先用临时图） |
| **M1 钓鱼原型** | 一个钓点、5 种鱼，从观察鱼影到上鱼的全流程，带调参面板 | **你玩 15 分钟还想继续玩** | P0：小溪水底图 |
| **M2 一天循环** | 时间和天气、家园图、鱼塘养殖、卖鱼、存档 | 能连续玩一周游戏日不出问题 | P1：家园图、NPC 立绘 2~3 个 |
| **M3 锦鲤育种** | 基因、花纹生成、繁殖、选别、品评会 | 能培育出肉眼可见、各不相同的锦鲤 | —— |
| **M4 内容填充** | 5 个钓点、40 种鱼、NPC、订单、外公笔记和剧情、装饰；替换全部正式素材 | 主线能从头玩到尾 | P1 + P2 全部 |
| **M5 Steam 准备** | 接入 Steam、商店页、试玩版，参加 Steam 新品节 | 试玩版通过 Steam 审核 | Steam 商店图、宣传片 |
| **M6 正式发布** | 1.0（或先上抢先体验） | —— | —— |
| **M7 种田更新** | 开荒、稻鱼共生、桑基鱼塘、料理 | —— | 田地相关素材 |

**建议**：Steam 商店页要尽早开（M2~M3 就可以），这样能提前积累愿望单。愿望单数量直接影响发售时的曝光。

## 6. 你现在可以开始准备的

1. **确认**[策划大纲](game-design.md)第 16 节的几个问题（视角、技术栈、游戏名、手柄）。
2. **准备图像 AI**（商用一般需要付费版），先生成 [美术指南](art-audio-guide.md) 里的 **P0 素材**：
   - 1 张主视觉（用来锁定整体风格）
   - 1~3 张鱼塘池底图
   - 1 张小溪水底图
3. **音乐不急**，M2 前后开始就行。
4. **Steamworks 注册可以稍晚**，M2 之后再办也来得及。

我这边确认后就可以同时启动 **A（项目骨架）** 和 **B（M0 鱼塘技术验证）**。素材没到位时我先用临时图，到了直接替换。
